# 0004. No packages for UBL 1.0 and UBL 2.0

- Status: Accepted
- Date: 2026-11-02

## Context

The library has a package for each UBL release from 2.1 to 2.5. OASIS also published UBL 1.0 (2004) and UBL 2.0 (2006). We did a test to find the value and the cost of a package for each of the two releases.

### UBL 2.0

- UBL 2.0 uses the same namespaces as all later 2.x releases, for example `urn:oasis:names:specification:ubl:schema:xsd:Invoice-2`. Each minor release of UBL 2 is backward compatible.
- The 2.1 and 2.5 packages parse all 13 official 2.0 examples. The output is valid against the 2.0 schemas and against the schemas of the release. The only difference in content is the `xsi:schemaLocation` attribute, which xsdata does not keep.
- xsdata can generate a 2.0 package with the current configuration. The package has 31 document types and 2.1 MB of code. The schemas add 2.8 MB.
- The 2.0 schemas set default values on code list attributes, for example `listID` and `listURI`. The generated classes write these values on export. Thus the output has attributes that are not in the input. The 2.1 schemas do not set these defaults.
- Some profiles still use UBL 2.0, for example the Danish OIOUBL 2.x. The main e-invoicing networks use UBL 2.1.

### UBL 1.0

- UBL 1.0 uses its own namespaces, for example `urn:oasis:names:specification:ubl:schema:xsd:Invoice-1.0`. The structure is also different. For example, `cac:BuyerParty` replaces `cac:AccountingCustomerParty`. A 2.x package cannot read a 1.0 document.
- xsdata can generate a 1.0 package. It has 8 document types. The output has the same default attributes as 2.0.
- The functions `to_xml()` and `detect_version()` use the 2.x namespaces. Support for 1.0 needs changes to these functions.
- The OASIS page for UBL 1.0 links only to a ZIP of the committee draft.

## Options

1. A package for UBL 2.0 and for UBL 1.0.
2. A package for UBL 2.0 only.
3. No new package. Add the 2.0 examples to the tests.

## Decision

Option 3.

- Each release reads the official UBL 2.0 examples in the round trip test.
- UBL 1.0 is not supported.

A 2.0 package adds only one function: export with a guarantee that the document is valid UBL 2.0. That does not justify 5 MB in the wheel and a special case in the tests. UBL 1.0 has almost no current use, and it needs changes to the core functions.

## Consequences

- The README claim "each release reads UBL 2.0 documents" is tested.
- `validate()` cannot do a check against the 2.0 schemas. To write UBL 2.0, users must not use elements that were added after 2.0.
- If users need 2.0 export, we can add a `v2_0` package with the normal steps for a new release. The test must then ignore attributes with schema default values.
